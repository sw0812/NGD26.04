# 공부 노트 — 이번에 쓰고 고친 코드 설명 (2026-11-11 ~ 11-12)

KASA 실내 탐색 드론 gz SITL. GPS 없이 **바닥 격자선을 카메라로 보고 위치를 알아내서** PX4 EKF에 넣는 게 핵심.

```

   (fused_line.py로 격자선 검출)                                   ↑
                                          옵티컬플로우(속도), IMU, 라이다(높이), 지자기
 전방/하향 영상 ──> ArUco 검출 ──> search_phase_node.py (미션: 탐색 → 구조경로 → 복귀 → 착륙)
```

## 1. 카메라 모델 — `PX4-Autopilot/Tools/simulation/gz/models/tarot680pro/model.sdf`

라즈베리파이 글로벌셔터 카메라(IMX296): 1456x1088 픽셀, 픽셀 크기 3.45 µm, 60 Hz.

렌즈 초점거리 f[mm] → 픽셀 단위 초점거리와 화각:
```
fx [px] = f[mm] / 0.00345          (픽셀 크기로 나눔)
HFOV    = 2 · atan(728 / fx)       (728 = 가로 1456 의 절반)
```
| 렌즈 | fx | 가로 화각 | 2.85 m 높이에서 바닥 보이는 폭 |
|---|---|---|---|
| 2.8 mm | 811.6 | 83.8° | 5.1 m |
| **3.2 mm (지금)** | **927.5** | **76.3°** | **4.4 m** |
| 4 mm | 1159.4 | 64.2° | 3.6 m |
| 6 mm | 1739.1 | 45.4° | 2.4 m |

- gz는 `<horizontal_fov>`(라디안)만 받음 → 위 식으로 계산해서 넣음. gz가 `/camera/camera_info`로 fx를 알려줘서 ArUco는 자동으로 맞음.
- **우리 코드(line_odometry, line_guidance)는 fx를 직접 받음** → 렌즈 바꾸면 `-p fx:=927.5`, `DOWN_FX=927.5` 같이 바꿔야 함.
- 전방 카메라: 기체 앞 0.10 m, 35°(0.6109 rad) 아래로 기울임 → 2~5 m 앞 바닥을 봄 (ArUco 미리 등록용).

## 2. 격자선 검출 — `fused_line.py` (새로 만든 것)

예전 방식(`grid_line_follow.py`)은 "선 굵기가 몇 픽셀"로 찾았음 → 렌즈 바꾸면 픽셀 굵기가 달라져 0개 검출.
새 방식은 **바닥 위 실제 크기(m)** 로 판정 → 렌즈/해상도가 바뀌어도 그대로 동작.

### 단계
1. **윤곽선 찾기** `detect_segments()`
   - 흑백 변환 → 절반 크기로 축소 → 가우시안 블러 → `Canny(15, 40)` 윤곽 → `HoughLinesP` 로 직선 조각
   - 각 직선 조각 양옆 ±4 px 밝기를 비교해서 **어느 쪽이 어두운지(극성)** 기록
2. **바닥에 투영** `FusedLine._ground()`
   - 픽셀 (u,v) → 카메라 광선 `ray = (u-cx)/fx·X + (v-cy)/fx·Y + Z`
   - 기체 자세 쿼터니언으로 회전 `R @ ray` (기체가 기울어도 보정됨)
   - 카메라 높이 `hc = 기체높이 - 카메라 z오프셋`, 광선이 바닥에 닿는 점 `t = hc / r_z`
   - 결과: 기체 기준 바닥 좌표 (앞 F, 오른쪽 R) [m]
3. **방향 분류** `edges()` — 기수 기준 ±25° 안이면 `along`(진행 방향 선), 수직이면 `cross`(가로지르는 선)
4. **짝 맞추기** `pair()` — 페인트 선은 "밝→어둠" 경계와 "어둠→밝" 경계가 **폭 3~25 cm 간격**으로 붙어 있음.
   짝이 있는 것만 진짜 선으로 인정 → 바닥 무늬/그림자 같은 외톨이 경계는 버림. 선 중심 = 두 경계의 가운데.
5. **직선 맞추기** `fit_along()` — 하향(발밑) + 전방(2~4 m 앞) 점들을 `R = lat + tan(psi)·F` 로 최소제곱
   → `lat`(선이 옆으로 얼마나 떨어졌나), `psi`(기수가 선과 얼마나 틀어졌나). 앞뒤 거리가 길어서 각도가 정확.

> 부호 버그 하나 고쳤음: 카메라 높이를 `h + z` 로 계산했었는데 NED에서 z는 아래가 + → `h - z` 가 맞음.

## 3. 위치 측정 노드 — `line_odometry_node.py`

20~30 Hz로 하향 영상마다:

1. `_fused_meas()` 가 fused_line으로 선을 찾음 (yaw=0을 넣어서 F=북쪽 거리, R=동쪽 거리로 바로 받음)
   - 남북 방향 선 → **E(동쪽) 위치** 측정, 동서 방향 선 → **N(북쪽) 위치** 측정
2. **버티포트 근처 선은 버림** — 반경 1.8 m 안에 찍힌 선은 상판 테두리일 수 있음 (`PAD_LINE_EXCLUDE_R`)
3. **스냅** `snap()` — "EKF 위치 + 선까지 거리" 를 가장 가까운 실제 격자선(위치를 미리 앎)에 붙임
   ```
   X_LINES = -2, 2, 5, 8, ..., 26, 30   (3 m 간격 + 바깥 테두리)
   Y_LINES = -2, 2, 5, 8, ..., 17, 21
   ```
   가장 가까운 선이 **0.7 m(`SNAP_TOL`) 넘게** 떨어져 있으면 어느 선인지 몰라서 버림.
4. **`max_innov` 검사** — 측정 위치와 EKF 위치 차이가 이 값 넘으면 버림 (기본 0.5 m)
   - 주의: 3번 스냅이 이미 0.7 m 이상은 버리므로, **max_innov를 0.7보다 크게 해도 실제로는 0.7과 같음**.
5. **EKF로 보냄** — `VehicleOdometry` 메시지 (`/fmu/in/vehicle_visual_odometry`)
   - 위치: 여러 선의 측정값 중앙값
   - 분산: `(meas_std × max(1, 높이/2))²` → 높을수록 덜 믿게. 측정 안 된 축은 100 m² (사실상 무시)

### meas_std 와 max_innov (30회 스윕으로 확인)
- `meas_std`: "내 측정 오차는 이 정도" 라고 EKF에 알려주는 값. **작을수록 EKF가 측정을 강하게 믿음.**
  - 실제 측정 오차는 ~1 cm로 매우 정확 → 작게(0.07~0.10) 주는 게 맞음
  - EKF 설정 `EKF2_EVP_NOISE=0.10` 이 하한이라 0.07보다 작게 줘도 효과 없음
- `max_innov`: "EKF 예측과 이만큼 넘게 다르면 버린다"
- **실패 패턴 (스윕에서 7번)**: meas_std 큼 → EKF가 측정을 약하게 반영 → 위치가 서서히 밀림
  → 0.5~0.7 m 넘게 밀리면 정상 측정이 전부 버려짐(바로잡을 수단 없음) → 계속 밀림
  → 약 2.3 m 밀리면 **옆 격자선(3 m 옆)에 스냅이 걸려 버림** → EKF가 한 칸 틀린 위치를 "맞다"고 믿고 고정
  → 실제 기체는 엉뚱한 곳, 필드 밖까지 나감.
- 결론: **meas_std 0.07~0.10 이면 max_innov 0.2~1.0 전부 성공.** 기존값 0.10 / 0.5 안전.

### CSV 로그 (`-p csv:=...`)
`t, img_stamp, err_n, err_e, vn, ve, roll, pitch, h, pn, pe`
- `pn, pe` = 측정 순간 EKF 위치, `err_n/e` = 측정 - EKF, → 측정값 = `pn + err_n`
- `img_stamp` 는 gz 시뮬 시간 = ulog 시간과 같음 → 실제위치(groundtruth)와 바로 비교 가능

## 9. 핵심 개념 정리
- **EKF2 EV(External Vision)**: 외부 위치 측정을 PX4 EKF에 넣는 입구. 우리는 격자선 위치를 여기로 넣음.
  - `EKF2_EV_CTRL=1` 수평 위치 사용, `EKF2_GPS_CTRL=0` GPS 끔
  - `EKF2_EVP_NOISE`: 측정 잡음 하한 (0.10 m). `EKF2_EV_DELAY`: 측정 지연 보정 (40 ms가 최적이었음, 적용은 미결정)
- **격자 모호성**: 격자선은 다 똑같이 생겨서 "몇 번째 선인지"는 EKF 위치로만 앎 → EKF 오차가 반 칸(여기선 0.7 m 스냅 범위) 넘으면 위험. 모든 실패의 근본 원인.
- **측정 정확도 vs EKF 정확도**: 측정은 ~1 cm로 정확한데 EKF 오차는 5~8 cm → 오차는 측정이 끊기는 구간(대각선, 회전)과 지연에서 생김.
- **NED vs ENU**: PX4는 NED(x=북, y=동, z=아래), gz/월드는 ENU(x=동, y=북). 코드에서 `drone_x = msg.y` 같은 변환이 그 때문.
